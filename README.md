# AIプロンプトメーカー V2.5

Android Chromeで、固定人物に衣装・シーン・表情・構図・仕上がりを組み合わせ、画像生成用の日本語プロンプトを作るツールです。HTML/CSS/JavaScriptのみ。外部ライブラリ・ビルド・API・サーバー・データベースは不要です。画像そのものは生成しません。

V2.5は `codex/ai-prompt-maker-v2-5` で開発しています。V2.4.1 semantic fixコミット `bfb8015ec4f779d4824ff70be05b983960775b15` がベースです。**main、既存のV2.1/V2.2系ブランチ、GitHub Pagesの公開元は変更していません。**

## V2.5の変更

人物の入力先が分かるよう、作成画面と保存設定の人物編集画面を同じ3グループにしました。

- **基本情報**：管理名・年齢/年代・「雰囲気・人物像」を常時表示します。内部キーは従来のdescriptionのままです。
- **外見**：初期展開。顔立ち・目・髪・肌/メイク・体型/身長・その他の身体的特徴を個別に入力できます。短くしたい場合は折りたためます。
- **一貫性**：初期折りたたみ。必ず維持する特徴と補足・一貫性指示を入力します。
- 雰囲気欄のそばに「顔・髪・体型などの外見は下の『外見』へ入力」と案内します。入力例を具体化しました。
- 新規保存は作成画面で入力した各欄を保存し、保存ダイアログでは設定名だけ指定します。上書きは保存設定の「編集」から行います。
- 人物カード自体は従来どおり初期折りたたみ。普段はクイック作成から保存済み人物を選ぶだけです。
- コンパイラ、内部キー、保存キー、version:4、旧データ移行は変更していません。descriptionの自動解析・自動分割はありません。過去にdescriptionへ集約された文章もそのまま保持します。
- 過去データを構造化したい場合は設定を複製し、既存編集画面で内容を各欄へ手動で移してください。履歴の保存済み文章は変わりません。

## V2.4.1の文章生成（維持）

人物詳細の文章生成だけを改善しました。短い名詞句は意味のまとまりごとにつなぎ、入力の多い人物も基本属性・雰囲気、顔・目、髪、肌・メイク、体型、一貫性・固定指定の6つの意味グループに分け、短文と段落で描写します。UI・保存形式・移行・コピー・履歴・JSON機能は変更していません。

- 年齢と人物説明、顔立ちと目、髪型と髪色、肌とメイク、体型・身長と身体特徴、一貫性と補足の順に整理します。年齢だけから性別や成人属性を追加しません。
- 旧項目を統合した改行と、現行の統合欄の読点区切りも読み込みます。例えば「ロングヘア＋暗めのブラウン」は「暗めのブラウンのロングヘア」、「自然な肌＋ナチュラルメイク」は「自然な肌にナチュラルメイク」と接続します。
- 身長の数値と体型が明確な場合は「身長165cm、健康的な体型で、すらっとした手足」のように統合します。
- 維持欄の属性名リストには維持する指示を付けます。入力済みの一貫性指示はそのまま使い、一般的な維持指示を重ねません。固定リストと対象が一致する強い維持指示は「特徴を維持し、特に…」の一文にまとめます。未知の特徴名にも維持欄の役割を残し、否定や異なる対象は無理に統合しません。
- 完全一致する行や既知の同じ目元の描写、説明冒頭に明示済みの年齢の反復を整理します。同じ「黒」でも目と髪の情報はそれぞれ残します。
- 長文・否定・未知の自由指示は無理に接続せず保持します。あらゆる自由文を自然にリライトする機能ではありません。関連づけを安全に判断できない場合は項目の意味を示す表現を残します。
- 冒頭の実写指定は維持し、補強は「現実的な質感を保った仕上がり」に短縮しました。光や質感の明示指定を優先するV2.4のルールは変えません。

## V2.4の補強ルール（維持）

UIと保存形式を維持し、プロンプトコンパイラに条件付き補強を追加しました。ユーザーの人物属性・衣装・場所などは創作せず、入力から明確に分かる撮影意図だけを補強します。見出しや「〜とする」「〜を指定する」等の仕様書表現は生成しません。

- **実写・フォトリアル／スマートフォン写真風**：質感の自由指定がない場合、「現実的な質感を保った仕上がり」を追加します。年齢・肌・髪・体型を追加しません。
- **友人撮影**：実写系で、演出・ポーズ・機材・距離などの指定がない場合に自然なスナップ表現を補強します。カメラ目線を打ち消す表現は追加しません。
- **自撮り**：カメラとの距離感を補強します。鏡・三脚・セルフタイマー・明示された距離や機材があれば控えます。スマートフォンの使用を勝手に決めません。
- **全身／顔アップ／バストアップ**：撮影範囲を明確化します。構図欄と専用欄の既知の同義表現は一度だけ出力します。未知の自由文同士は推測して削除しません。
- **夜**：「夜」「夜間」「深夜」や否定されていないナイトパーティを認識した場合、照明指定がなければ夜の環境光を補強します。ネオン・街灯など具体的な光源は創作しません。昼や夜の否定、光に関する自由入力があれば控えます。
- 明確な短文「ナイトパーティでおさけをのんでる」だけ「ナイトパーティでお酒を飲んでいる」に表記整理します。長文・否定・引用は書き換えません。
- 画像全体→人物と一貫性→衣装→シーン→表情/動作→構図/撮影方法→仕上がり→補足の順です。ユーザーの矛盾する入力も両方保持します。
- 管理名・ネガティブ・内部情報は通常文にも補強判断にも使いません。ネガティブは入力のまま別コピーします。
- **表現形式だけでも生成できます。** 初期状態でも選択済みの9:16と実写系に基づく短い文章が表示され、コピーできます。空欄の人物・衣装等は補いません。
- 保存キー `ai-prompt-maker-v2-2` とデータversion:4は変更しません。新しい移行処理はありません。既存の設定をそのまま使え、過去の履歴文章は保存時のまま保持します。履歴から設定を復元するとV2.4で再生成します。
- 判断は限定した語句のルールによります。補足・一貫性欄など自由指示がある場合は安全のため補強を控えることがあります。自由文のあらゆる矛盾を判定する機能ではありません。

## 普段の操作（V2.2 UI修正版を維持）

**普段は、クイック作成から保存済み設定を選ぶだけで使えます。** 人物・衣装・シーン・表情/動作・構図・仕上がりを選んで「コピー」を押してください。

新しい人物を登録する場合は人物カードを開きます。「基本情報」と初期展開された「外見」に入力し、必要に応じて「一貫性」を開きます。「雰囲気・人物像」に外見をすべてまとめず、顔・髪・体型などはそれぞれの欄へ入力してください。

- 髪型と髪色、肌とメイク、体型と身長、固定/維持する特徴、その他/補足を統合しました。
- 各欄に具体例を表示します。例は入力値・保存データ・生成文章には入りません。
- textareaは基本2行、雰囲気・人物像・必ず維持する特徴・補足は3行。入力と展開に合わせて高さを自動調整し、長文は欄内をスクロールできます。手動リサイズは不要です。
- 下部は48pxの「結果 / コピー」バーと64pxの3タブナビです。safe-areaと余白を含めて本文下部のpaddingを確保しています。
- 人物情報は年齢→説明→顔→髪→目→肌/メイク→体型/身長→身体的特徴→維持する特徴→補足の順に生成します。
- 保存済み人物を読み込んで入力を変更しても元設定は変わりません。カードの「別名で保存」は新規登録です。元設定を上書きする場合は「保存設定」の「編集」→「変更を保存」を使います。

## 少ない操作で作る

1. 「作成」上部のクイック作成で、人物・衣装・シーン・表情/動作・構図/カメラ・仕上がりを選択します。お気に入りは★付きで上に並び、最大2件のお気に入りと最近使った1件をタップ候補として表示します。
2. 設定を変更したいときだけ、そのカテゴリのカードを開きます。閉じたカードに設定名と✓が表示されます。詳細欄はさらに折りたたまれています。
3. 完成文章は自動更新されます。画面下部の「結果」で完成文章へ移動し、「コピー」で通常プロンプトをコピーできます。
4. ネガティブは別欄・別ボタンでコピーします。空欄からは文章を生成しません。
5. 残したい組み合わせは「履歴に保存」。最新100件まで保存し、101件目で最も古い履歴が除かれます。

管理名は一覧・カード・履歴で識別するためのものです。通常プロンプトには出力しません。管理名のみでは通常プロンプトを作成しません。人物や衣装の説明など、生成に使う内容も入力してください。

## 6種類の設定

| カテゴリ | 設定できる内容 |
| --- | --- |
| 人物 | 管理名、年齢、人物説明、顔立ち、髪、目、肌/メイク、体型/身長、身体的特徴、必ず維持する特徴、補足 |
| 衣装 | 管理名、衣装説明、種類、色、素材、デザイン、靴、アクセサリー、その他 |
| シーン | 管理名、状況、場所、時間帯、行動、周囲の人物、照明、雰囲気、小物、背景、その他 |
| 表情・動作 | 管理名、表情、視線、口元、身体の動作、手の動き、人物同士のやり取り、その他 |
| 構図・カメラ | 管理名、構図説明、撮影範囲、方向、高さ、距離、アングル、ポーズ、視線、撮影者、機材感、レンズ感、背景ボケ、その他 |
| 仕上がり | 管理名、比率、表現形式、機材感、光、色調、被写界深度、画質/質感、その他 |

比率: 9:16 / 4:5 / 1:1 / 3:4 / 16:9。
表現形式: 実写・フォトリアル / スマートフォン写真風 / イラスト / アニメ。

衣装は衣装説明だけでも保存できます。他カテゴリも必要な項目だけで構いません。未入力の詳細は生成文章から除外されます。既定の比率は9:16、表現は実写・フォトリアルです。比率は生成サービス側でも指定が必要な場合があります。

## 保存設定を管理する

「保存設定」のカテゴリ選択で1カテゴリだけ表示します。

- 読み込み: 作成画面へ反映し、そのカードを閉じます。元の保存設定は変更しません。
- 編集: 別の編集画面で内容を変更し、明示的に保存します。ID・作成日時・お気に入りは維持し、更新日時を変更します。作成途中の入力は変更しません。更新版を使う場合は再度読み込んでください。
- 複製: 新しいIDで「（コピー）」を付けて保存します。
- 削除: 確認後に削除します。作成途中の入力と過去の履歴は残ります。
- ☆/★: お気に入りを切り替えます。保存一覧とクイック選択で優先表示します。

作成画面から保存する場合は新規保存です。同じ名前でも別の設定になります。管理名を省略した場合は内容から名前候補が作られ、保存時に変更できます。

## 文章の組み立てと履歴

AI APIを使わず、入力内容から決定論的に指示文を組み立てます。比率/表現→人物→外見/維持する特徴→衣装→シーン→表情/動作→構図→カメラ/視点→光/色/質感→補足の順です。管理名、空欄、ネガティブは通常文章に混ぜません。未入力の光や肌加工等は追加しません。

表情・動作と構図の視線が同じなら一度だけ出力し、異なる場合は両方出力します。旧人物の表情は通常の人物UIには表示しません。初回移行時に「表情・動作」の表情が空欄なら旧表情を引き継ぎます。旧人物プリセットを読み込む場合も同様です。既に表情が指定されていればそちらを優先します。表情欄を消すと生成文から除外されます。旧表情自体は内部データに残し、JSONにも含めます。

履歴は人物・衣装・シーン・比率・日時を短く表示し、「プロンプトを見る」で全文を展開します。通常・ネガティブを個別コピーでき、確認後に設定復元・削除ができます。履歴の完成文章は保存時の文章をそのまま保持し、復元後の作成画面ではV2.4の文章生成処理で再構成します。

## V2 / V2.1データとの互換性

| アプリ | localStorageキー | データversion |
| --- | --- | --- |
| V2 | `ai-prompt-maker-v2` | 2 |
| V2.1 | `ai-prompt-maker-v2-1` | 3 |
| V2.2 / V2.4 | `ai-prompt-maker-v2-2` | 4 |

V2.2データがない初回だけ、V2.1を優先し、存在しなければV2から移行します。**旧キーは変更・削除しません。** 以降はV2.2キーのみ使用し、二重移行しません。旧版で後から行った変更は自動同期しません。

作成途中の入力・保存人物・履歴の入力設定で、次の統合を行います。

| 元の項目 | 新しい項目 |
| --- | --- |
| 髪型＋髪色 | 髪 |
| 肌・肌質＋メイク | 肌・メイク |
| 体型＋身長 | 体型・身長 |
| 固定したい特徴＋生成時に維持したい特徴 | 必ず維持する特徴 |
| その他の特徴＋補足 | 補足 |

両方ある場合は改行で区切って情報を残します。一方だけならその内容を使用し、両方空欄なら空欄です。保存設定のID・名前・作成/更新日時・お気に入り・最近使用・履歴の完成文章/日時/IDは維持します。V2の画像スタイルも従来通り変換します。

新しいJSONはversion:4で書き出し、version:2/3/4を読み込めます。version:4を読む際は統合を再実行しません。履歴の完成文章は保存時の文章を保持しますが、設定復元後の作成画面ではV2.4の生成処理で文章を再構成します。

読めない保存データは自動上書きせず警告します。正しいJSONの確認付き復元で再開できます。元保存領域を残す分だけlocalStorageの使用量は増えます。容量不足時はJSONへバックアップしてください。

同じ端末・ブラウザ・オリジンでのみ自動移行できます。GitHub Pagesとraw.githackは別の保存領域です。raw.githackのコミット固定URL同士は保存領域を共有します。別端末・別オリジンへはJSONで移してください。

## JSONバックアップと復元

「保存設定」下部の「バックアップ・復元」から操作します。

- 書き出し: 全6カテゴリ・お気に入り・最近の使用設定・履歴・作成途中の入力をJSONファイルへ保存します。
- 読み込み: ファイルを選択します。JSON形式、version、項目型、ID、日時、メタデータ、履歴100件上限を確認します。10MBまで対応します。
- 復元前に設定/履歴の件数と置換確認を表示します。キャンセルするとデータは変わりません。
- V2形式（version: 2）、V2.1形式（version: 3）のJSONも読み込めます。
- 保存に失敗した場合は、既存のデータ・画面入力を置き換えません。
- 保存データが破損しているときの書き出しには、取得可能な元の保存文字列を `recoveryData` に含めます。これは調査用で、自動復元対象ではありません。

ブラウザデータを削除すると保存内容も消えます。バックアップを定期的にダウンロードし、ファイルがあることを確認してください。サーバー送信・クラウド同期は行いません。複数タブ同時編集の競合は未対応です。1つのタブで使ってください。

## ファイルと管理方法

- `index.html`: 3タブ、クイック作成、入力カードの配置、結果、各ダイアログ
- `style.css`: 紫系デザイン、折りたたみ/コンパクト表示、固定ナビ、安全領域、キーボード時の調整
- `script.js`: SCHEMA（入力項目定義）、生成文章、保存管理、移行、コピー、バックアップ
- `tests/v2-1.test.cjs`: V2.4向けに更新した外部依存なしの回帰テスト（ファイル名を維持）
- `tests/prompt-compiler.test.cjs`: 新コンパイラの入力保持・順序・空欄・決定論などのテスト
- `README.md`: 使い方、互換性、確認方法

項目を追加する場合はJavaScript先頭のSCHEMAと文章生成処理を確認してください。保存キー・項目キーの変更には移行処理が必要です。色とサイズはCSSで管理します。

## 検証方法

```bash
node --check script.js
node tests/v2-1.test.cjs
node tests/prompt-compiler.test.cjs
node tests/v2-4-compiler.test.cjs
node tests/v2-4-1-person.test.cjs
node tests/v2-5-ui.test.cjs
git diff --check
```

DOM・localStorage・Clipboard APIを模擬して実際のJavaScriptを実行するテストです。ブラウザの見た目、実際のクリップボード、ダウンロード、キーボード動作は実機確認が必要です。環境のソケット制限でChromiumを起動できないため、ブラウザテストは実行していません。Playwright等の依存関係は追加していません。

V2.5ではJavaScript構文チェック、差分チェック、既存の回帰テスト65項目と既存コンパイラテスト25項目とV2.4補強テスト22項目、人物統合テスト30項目、V2.5 UI/保存経路テスト13項目（計155項目）が成功しました。人物/衣装/構図だけの入力、全項目、固定/維持する特徴、管理名除外、重要情報保持、否定指定、決定論、旧V2.2/V2.3/V2.3.1保存データ、鏡越し/三脚/カメラ目線、長文、明示された光・質感の優先も確認しています。既存テストは削除せず、形式だけの生成と限定した表記整理に対応する期待値を更新しました。

PCで動かす場合は `python3 -m http.server 8000` で http://localhost:8000 を開けます。スマートフォンのlocalhostはPCとは別です。AndroidではHTTPSの確認URLを開いてください。

### Android Chromeでの確認

1. 通常タブで確認URLを開き、同じブラウザ・同じ配信元にある既存の設定・入力・履歴が残っているか確認する。まずJSONバックアップを取る。
2. 6カテゴリをクイック選択し、閉じたカードの名前、✓、自動生成文章を確認する。
3. カードと詳細欄を開閉し、新しい詳細を入力する。カード内で保存し、再読み込み後も残ることを確認する。
4. 保存設定のカテゴリ切り替え、編集、複製、お気に入り、削除を試す。読み込みと編集で元設定/作成入力が意図せず変わらないことを確認する。
5. 下部の「結果」「コピー」とネガティブコピーを試し、メモアプリへ貼り付ける。
6. 履歴保存→入力変更→復元→削除を試す。
7. JSONをダウンロードし、入力を変えてから読み込み、キャンセルと復元の両方を試す。
8. V2.2と同じ設定で段落の順序、重要情報の保持、ネガティブ分離を確認する。全身/自撮りの補助が意図に合うか確認する。
9. キーボード表示中の画面下部、Androidシステムナビ、縦/横向き、長い名前や文章の表示を確認する。
